# Needle v1

v1 freezes the decision. Candidate generation is unchanged. The structural recognizer and the evidence machinery stay loaded. The final choice is the code-length rule with the digit-literal charge, on the eight candidates that rule already sees. Learned confidence and alternatives are reported beside that choice. They do not replace it.

```text
candidate generation
        ↓
structural recognizer / evidence machinery
        ↓
96.25% code-length symbolic selector
        ↓
learned confidence + alternatives
        ↓
regex / AST
```

The 2,145-parameter override remains in `pattern_induction/safe_override.py`. Default inference does not load it.

## What the experiments found

The project built neural rankers, AST encoders, compositional priors, a real-world teacher bank, and a conservative neural override. The override could name 27 symbolic mistakes on BENCH-C and introduced 26 new ones. Its score was 0.9633 against the symbolic 0.9625. The oracle union of those two programs is 0.9731, so better choices exist in the set. The run did not find a safe way to identify them. That is a v2 problem.

| Measurement | BENCH-C | Role |
| --- | --- | --- |
| v1 selector | 0.9625 | the decision, recorded and recomputed |
| learned override | 0.9633 | experiment, 27 fixes and 26 regressions |
| union of selector and Needle's program | 0.9731 | known choices, not safely identified |
| product-contract candidate oracle | 0.980 | ceiling of the generator under the product clip |
| gpt-5.6-terra | 0.981 | teacher score from the earlier frontier pass |

v1 ships at 0.9625. v2's target is the remaining point or two, without the regressions.

## Frozen evaluation

The development benchmark is BENCH-C, 554 tasks, every visible string, the same eight-candidate code-length rule. The stored score is 0.9624725631768952. Recomputing it with `symbolic_pick` gives 0.9624699157641396. The same rule on only the first four strings of each task scores 0.9190. `needle()` passes every example the caller provides to the selector, so a six-string call is the 0.9625 protocol and a four-string call is the shorter one.

BENCH-E was opened once after this freeze. The file is unchanged, sha256 `f370a1707179ede5212d360751c5fb23ae7b6f507ec75665cd727dffc920ba9d`, n=100, seed 2507. The same full-visible selector scores **0.9848**. The four-string clip on that file scores 0.9656. Nothing was changed after those numbers.

## Calling it

```python
from pattern_induction.needle import needle

result = needle(["INV-2024-10021", "INV-2026-88310", "INV-2025-00418"])
result.regex       # ^INV-\d{4}-\d{5}$
result.ambiguous   # True when the recognizer names a different language, or the runner-up is within one bit
result.alternatives  # other languages, not spellings of result.regex
result.confidence  # margin, agreement, and the one-bit band; the regex stays
```

One example abstains. A non-string raises `NeedleError`. The selector sees each example whole. The recognizer reads the first four, each clipped to 32 characters. Before that split, `needle()` clipped the selector's input too: 20 of the 21 BENCH-C tasks with an example longer than 32 characters changed winner, and `needle()` scored 0.947 there instead of 0.9625. The recorded BENCH-C and BENCH-E scores are the whole-string selector and do not change; a missing checkpoint still returns the symbolic regex, with confidence taken from the code-length margin alone. From the repo root, `uv run needle INV-2024-10021 INV-2026-88310 INV-2025-00418` prints the same regex.

A few real calls are in `results/needle/showcase.md`. The selector is 2–4 ms. The recognizer is cached by canonical AST identity and subtree matches, so the version examples take 1.7 seconds on this CPU instead of 6.9, and the other five showcase calls finish in 0.13–0.49 seconds. Loading the recognizer brings the process to about 355 MB. The profile is `results/needle/inference.md`. Recomputing BENCH-C after that pass is still 0.9624699157641396. BENCH-E was not scored again.
